# Робота 1. Три предметні мови

## 1. Markdown (.md)
* **Задача й користувач:** Спеціалізована мова розмітки текстових документів, орієнтована на розробників або користувачів GitHub тощо.
* **Що робить простим:** Дозволяє миттєво форматувати текст (заголовки, списки, таблиці) за допомогою простих символів прямо під час набору, позбавляючи потреби використовувати громіздкі візуальні редактори чи писати складні теги HTML.
* **Де її межа:** Нею не варто намагатися робити складні макети з анімаціями чи інтерактивними елементами.


## 2. CSS-селектори
* **Задача й користувач:** Призначені для веб-розробників, щоб описувати правила адресації та знаходження конкретних елементів інтерфейсу в DOM-дереві.
* **Що робить простим:** Дозволяють в один короткий рядок вибирати потрібні вузли (наприклад, `.card > button:hover` чи `[type="checkbox"]:checked`) без необхідності вручну писати складні алгоритми перебору елементів та перевірки умов у JavaScript.
* **Де її межа:** Нею не варто описувати правила стилізації, динамічну обробку даних — селектори вміють лише вказувати на елемент, але не визначають, що з ним робити.


## 3. JSX
* **Задача й користувач:** Зручний синтаксис для React-розробників, який дозволяє писати HTML-теги прямо всередині JavaScript-коду.
* **Що робить простим:** Дозволяє візуально описувати дерева HTML-елементів всередині JS-функцій замість того щоб через купу команд JS створювати кожен тег окремо на кшталт - `document.createElement()` та `appendChild()`.
* **Де її межа:** Вона призначена лише для опису того, що має відображатися на екрані; нею не варто робити обробку даних чи запити до сервера — для цього використовується звичайний JavaScript.

## Git - теж предметна мова
* **Задача й користувач:** Зручна мова для опису змін у файлах та керування їхньою історією чи версіями проєкту, їм користуються не лише розробники, а й письменники, дизайнери, дослідники - усі, кому потрібно відстежувати версії/історію своєї ороботи та узгоджувати зміни з іншими.
* **Що робить простим:** Дозволяє описувати стан проєкту командами(`commit`, `branch`, `merge`) замість того щоб вручну копіювати файли чи запам'ятовувати зміни чи яка версія актуальна. Git сам відстежує зміни у версіях та дозволяє повернутися до будь-якої з них.
* **Де її межа:** Вона призначена для фіксації  змін у файлах, вона не пояснить як працює чи чому зроблений код, вона не підійде для опису логіки й вигляду програми.
